# Business Logic Map

This document names the business operations that must remain clear during rewrite.

## Create Technical Container

Business goal: create a locked calibration container that can safely calibrate future specimen sessions.

Inputs:

- operator
- machine/setup config
- detector aliases
- nominal distance, usually 2 cm or 17 cm
- technical measurements: AgBH, dark, empty, background
- PONI files generated by auto PONI or selected by operator

Rules:

- PONI must come from actual files, not memory cache.
- PONI distance must match allowed nominal range.
- PONI metadata must match detector geometry.
- Technical H5 must contain real aliases, not duplicated `SAXS/WAXS` aliases unless those aliases are actual detectors.
- Lock is blocked by hard validation errors.
- AgBH peak QC is warning-only.

## Create Session Container

Business goal: create a specimen measurement container that embeds a technical calibration snapshot.

Inputs:

- specimen ID text
- operator
- project/study metadata
- technical container
- measurement points
- detector frames and raw files

Rules:

- Technical data is copied into session container before/while measuring.
- Session metadata must preserve specimen/project/study/operator.
- Measurement data is stored under `/entry/measurements`.
- Analytical measurements are stored under `/entry/analytical_measurements`.
- Once measured or locked, edits are restricted and must be audited.

- `src/difra/gui/session_manager_*`

## Edit Archived Session Metadata

Business goal: correct project/study/specimen metadata when operator scanned or selected wrong values.

Rules:

- Project/study can be edited in archive.
- Specimen ID can be edited when authorized.
- Changes must update root attrs and embedded state.
- Specimen ID changes must be auditable.

## Repair Session Technical Section

Business goal: replace wrong embedded calibration in already-created session containers without losing measurement data.

Rules:

- Match session to corrected technical container by technical container ID.
- Before rewrite, copy original session to `.h5old`; if it exists use `.h5old2`, etc.
- Replace only embedded technical/calibration section.
- Keep `/entry/measurements` and `/entry/analytical_measurements`.
- Update `meta_json.CALIBRATION_GROUP_HASH`.
- Update sidecar `_state.json` when present.
- Mark session `transfer_status=req_resend`.

- `src/difra/gui/session_technical_rewrite_service.py`

- `tests/test_session_technical_rewrite_service.py`

## Upload To Matador

Business goal: upload technical calibration and specimen sessions so Matador can ingest them.

Inputs:

- session H5
- old-format ZIP payload
- calibration ZIP payload
- resolved Matador specimen ID
- Matador project/study/machine IDs

Rules:

- `NOT_COMPLETE` containers cannot be sent.
- Real uploads register files first, upload bytes to presigned URLs, then poll file status.
- Successful uploaded files reach `HASH_VERIFIED`.
- Matador can be slow. Pending verification is normal.
- `REQ_RESEND` containers should remain resend candidates until verification succeeds.

## Generate Analyst Report

Business goal: email or generate a ZIP of integrated detector plots for valid measured containers.

Rules:

- One PNG per specimen.
- PNG contains one subplot per detector alias.
- PONI files used for integration are included in the ZIP.
- Manifest records PONI source/hash and source data diagnostics.
- 2 cm containers use WAXS range.
- 17 cm containers use SAXS range.
- If q coverage is incomplete, do not fake or extrapolate the report image.
